## 本轮新增数据契约

### 会话历史

```http
GET /sessions?candidate_id={candidate_id}&project_id={project_id}&limit=50
```

会话摘要由后端 Session Store 返回，包含当前主题、回答数量、平均分、评审模式和更新时间。前端启动时优先恢复最近的服务端会话；浏览器 `localStorage` 仅保留兼容缓存，不作为历史事实源。

### 会话复盘

```http
GET /sessions/{session_id}/report
```

报告聚合在后端完成。前端只展示返回的题数、平均分、主题、优势、弱项、证据 ID、逐题记录和下一轮方向，不从 `history` 临时计算业务结论。

### 会话结束

```http
POST /sessions/{session_id}/complete
```

会话至少完成一次回答后可由用户显式结束。结束操作幂等，状态持久化为 `completed`；前端锁定回答输入并自动进入服务端复盘报告。已结束会话不能继续提交回答。

### 候选人能力画像

```http
GET /candidates/{candidate_id}/profile
```

画像直接读取 Candidate Profile Store 中持久化的主题分数、最近分数、趋势、样本数和薄弱项。每个薄弱项可携带最近一次来源会话、问题序号、问题文本和 evidence ID；前端可据此打开对应服务端会话报告并展开目标记录。旧画像没有来源字段时继续显示兼容空态。

## 后续怎么做

页面层已经补齐，后续工作转向“完善数据与闭环”，优先级如下：

1. Analyzer 扩展
   - 按插件边界增加 Python、前端项目等 Analyzer。
   - 不修改现有 Review Agent 页面数据边界。

2. 响应式与桌面验收
   - 继续覆盖 1280、1024 和窄窗口状态。
   - 涉及 Tauri 窗口配置时再运行 Rust 构建验证。

3. 自动化回归
   - 为 01–07 的导航、空态、加载态、错误态和主操作补充浏览器回归。
   - API 变化继续同步 OpenAPI、后端测试、`frontend/src/api.js` 与前端 API 测试。

## 统一完成标准

后续新增或修改页面时必须同时满足：

1. 只使用 OpenAPI 中真实存在的数据和写操作。
2. 适用的初始、加载、空、成功、失败、禁用状态可见且可恢复。
3. 主操作、导航、页签和表单是真实交互。
4. 评价、报告和画像不在前端生成业务结论。
5. 保留键盘焦点、语义标签和 reduced-motion 支持。
6. 运行受影响层测试、`npm test`、`npm run build` 和浏览器 Design QA。

## 暂不扩展

- 报告 PDF 导出、公开分享和团队权限。
- 在接口未定义前增加题数、时长、难度等不可执行设置。
- 为画像引入大型图表库或伪造精确趋势。
- 把 Evidence-first 工作台退化为通用聊天首页。
