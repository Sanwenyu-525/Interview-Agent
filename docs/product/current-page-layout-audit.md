## 总体结论

当前界面已经形成了清晰的浅色工作台风格，主导航、语义色、全局焦点样式和 Evidence-first 的产品方向基本成立。主要问题不在“缺少视觉设计”，而在于关键任务入口、跨页面层级和窄屏重排没有完全收口：空状态把“添加项目”藏在 `+` 菜单中；项目资料页在无项目时仍展示伪项目信息；移动端导航与页面标题重叠；设置页的信息密度、滚动和操作层级偏重。上述问题会让首次用户难以理解下一步，也会削弱不同页面属于同一产品的感觉。

## 审计步骤与页面健康度

1. 空项目面试工作台（桌面端）：一般，视觉稳定，但首次任务入口不够直接。
2. 项目资料空状态（桌面端）：较差，状态语义矛盾且页面利用率低。
3. 应用设置（桌面端）：一般，功能完整，但层级和滚动负担偏重。
4. 空项目面试工作台（移动端）：较差，页面标题与导航触发器发生竞争。
5. 移动端导航抽屉：良好，结构清楚，但主操作在无项目时仍呈禁用状态。
6. 应用设置（移动端）：较差，标题、状态、配置摘要和表单在单列中堆叠过密。

## 问题与改进方案

### P0-1 首次任务入口被隐藏【已实施】

当前问题：空项目工作台告诉用户“从输入框左侧的 `+` 添加项目目录”，但输入框和“新建复盘”同时处于禁用状态，真正可执行的主任务被隐藏在图标菜单里。用户需要先读说明、理解 `+` 的含义、再打开菜单，才能发现“选择文件夹作为工作区”。这是当前主流程最大的可发现性问题。

优化建议：在空项目消息区直接提供唯一主操作“添加项目目录”，并在旁边保留简短说明“支持源码、配置和 UTF-8 文本文档”。输入框左侧的 `+` 继续作为熟练用户入口，但不承担首次引导。禁用的“新建复盘”应显示可理解原因，或在无项目时转为同一个“添加项目”动作。

实施步骤：

1. 在空项目状态组件中加入“添加项目目录”主按钮，直接复用现有目录选择与上传处理函数，不新增业务逻辑。
2. 将空状态收敛为“说明 + 一个主按钮 + 一条能力限制”，移除重复的路径说明。
3. 为“新建复盘”补充禁用原因；若产品允许，改为触发同一添加项目流程。
4. 增加空状态测试：键盘可到达主按钮，触发后打开目录选择；失败后保留可读错误和重试入口。

### P0-2 无项目状态展示了伪项目信息【已实施】

当前问题：项目资料页在没有项目时仍显示“未命名项目”“upload”“0 条可追溯证据”和“打开项目目录”。这些字段看起来像系统已经创建了一个项目，与页面中央“先添加一个项目”相矛盾；“打开项目目录”在此时也缺少有效目标。

优化建议：无项目时只展示真实状态，不渲染项目名称、来源类型、证据计数和目录操作。空状态应直接提供“添加项目目录”入口，并说明添加后会得到结构、技术栈、流程和证据。只有项目状态为 ready 或至少存在有效项目标识时，才显示项目元数据和目录动作。

实施步骤：

1. 以 `projectReady` 或有效项目标识作为项目页头和操作区的渲染条件。
2. 无项目时使用独立 `ProjectEmptyState`，标题改为“尚未添加项目”，提供直接操作。
3. 上传、分析失败时展示真实阶段与恢复动作，不回退为“未命名项目”。
4. 为“无项目、上传中、分析失败、分析完成”四种状态补充界面测试。

### P0-3 移动端导航按钮与页面标题重叠【已实施】

当前问题：390px 视口下，导航触发器位于 `x=12, y=50, 74.6×40`，设置页标题容器从 `y=50.8` 开始，两者实际占用同一垂直区域。截图中“导航”按钮遮挡了“应用设置”眉题；工作台标题也被迫从按钮右侧开始，造成标题基线不一致。

优化建议：移动端建立固定的页面工具栏槽位：第一行只放导航按钮和当前页面名称，内容页头从下一行开始。不要通过给不同页面增加 `padding-left` 来绕开按钮，因为设置、项目和工作台的页头结构不同，容易继续产生重叠。

实施步骤：

1. 将 `mobile-nav-trigger` 从内容绝对定位改为移动端 `MobilePageBar` 的正常文档流子元素。
2. 页面主体统一从工具栏下方开始；删除各页面为导航按钮设置的局部左内边距补丁。
3. 在 320、390、620、920px 验证标题、面包屑、状态和右侧操作不会重叠。
4. 增加长页面标题与 200% 缩放用例，检查换行后工具栏高度可自动增长。

### P1-1 跨页面的页头和内容框架不一致【已实施】

当前问题：工作台使用“顶栏 + 浮动对话卡”，项目资料使用几乎占满视口的大型内容卡，设置页则使用“页头 + 页签 + 左侧配置列表 + 右侧表单”。同一级导航页面的标题位置、顶部留白、内容起点、圆角和页面边界变化较大，用户切换页面时会感到布局重新建立，而不是在同一个工作区内换任务。

优化建议：统一一级页面框架，明确四个固定槽位：移动/桌面导航、页面标题区、页面级操作区、内容区。允许工作台、资料页和设置页拥有不同内容结构，但页面标题的基线、外边距、最大宽度和圆角层级应一致。页面容器只保留一层主表面，内部区域优先通过留白和明度分组。

实施步骤：

1. 提取轻量 `PageFrame` 与 `PageHeader`，只统一结构和间距，不重写各页面业务组件。
2. 统一标题字号、眉题、说明文字、状态和右侧操作的排列规则。
3. 逐页迁移工作台、项目资料和应用设置；每迁移一页即做桌面、窄屏和移动端截图对比。
4. 删除迁移后仅用于旧页头定位的覆盖样式，避免继续叠加补丁。

### P1-2 设置页操作链路过长，保存动作容易离开视野【已实施】

当前问题：桌面设置页同时展示应用页头、主题切换、设置页签、模型列表、配置状态和完整表单。右侧表单自身为滚动容器，实测可视高度 534px、内容高度 665px，“保存配置”位于首屏下方。移动端又将这些区域全部串联为长单列，用户先经过主题、页签、状态、配置卡，再进入“新增大模型配置”，难以快速判断自己是在查看、编辑还是新建。

优化建议：把设置页拆成清晰的“选择对象 → 编辑对象 → 保存结果”路径。桌面端保留列表与表单，但为表单提供固定标题和粘性操作栏；移动端先展示配置列表，点击后进入独立编辑状态或展开详情。新建和编辑必须在标题、默认值和主按钮文案上明确区分。

实施步骤：

1. 增加显式视图状态：浏览配置、创建配置、编辑配置；不改变后端接口。
2. 将“测试连接 / 保存配置”放入表单底部粘性操作栏，并在未修改时清楚显示禁用原因。
3. 移动端将已配置列表折叠为摘要，选择配置后再展示表单，避免列表与表单同时争夺首屏。
4. 检查保存成功、失败、连接测试中和未保存离开等状态，确保反馈靠近操作区。

### P1-3 信息层级依赖过多容器和分隔线【已实施】

当前问题：设置页同时使用页面外框、页头分隔线、页签线、左右分栏线、列表卡片边框和表单行边框；项目资料空状态又把少量内容放入一个接近全屏的大卡片。页面边界很多，但真正的主任务和信息关系不够突出，且与项目“少线层级”的设计规范不完全一致。

优化建议：保留有真实语义的线——可拖拽分栏、独立滚动边界、表单焦点和错误状态；其他分组优先使用 16–24px 留白、标题字重、表面明度和内容岛。空状态不需要通过全屏卡片强调，可使用居中的内容区和明确主按钮。

实施步骤：

1. 对工作台、项目资料和设置页做一次“线条审计”，为每条满宽横线、满高竖线和重复边框标注语义。
2. 删除没有滚动、拖拽、数据对齐或状态语义的线，先用间距和表面层级替代。
3. 同一信息组只保留一层常驻边界；有外框时取消内部重复分隔。
4. 用缩略截图检查页面首先呈现的是“主问题与动作”，而不是行列网格。

### P1-4 设计 Token 已建立，但旧样式仍在制造视觉漂移【已实施】

当前问题：项目已有语义色、间距、字号和圆角 Token，也有基础按钮与表单 primitive；但 `styles.css` 已约 3950 行，仍包含约 151 种不同的十六进制颜色写法和大量 3–16px 的直接圆角值。同一个按钮、卡片、空状态和页头在不同页面因此呈现不同高度、边框、圆角和弱文本颜色。

优化建议：不做一次性样式重写，只对本次涉及的页面逐步迁移到语义 Token 和现有 primitive。优先统一高频基础形态：页面框架、主/次按钮、图标按钮、空状态、状态徽标、表单字段和卡片。保留特殊形态时必须说明其语义，而不是按页面新增颜色或半径。

实施步骤：

1. 以当前三类页面为范围，列出硬编码颜色、半径和控件高度，映射到现有 Token。
2. 先统一主按钮、图标按钮、弱文本和表单字段，再处理页面容器。
3. 每次迁移删除被替代的旧选择器，避免在文件末尾继续增加覆盖层。
4. 增加基础组件快照或结构测试，防止后续页面重新硬编码同义样式。

### P1-5 小字号、低对比占位文字和点击区域存在可访问性风险【已实施】

当前问题：设置页说明文字实际为 10px，侧栏为 11px；空工作台禁用输入框的占位文字约为 `#aaa49a` 对浅色表面，对比度约 2.45:1。可见操作中还存在低于项目 32×32px 最小点击区的控件，例如标题栏按钮约 36×30px、“新增配置”约 52×15px、“测试/编辑”约 36×30px。全局 `:focus-visible` 已存在，这是优点，但截图无法证明完整焦点顺序、读屏标签与菜单 Escape 行为。

优化建议：正文说明文字不低于 12px，移动端表单说明建议 13px；禁用状态不能只依赖低对比文字，应保留可读原因。所有按钮至少 32×32px，移动端关键操作至少 40px 高。保留当前全局焦点环，并对抽屉、附件菜单和设置页签做实际键盘与读屏验证。

实施步骤：

1. 将 10–11px 用户说明文字迁移到 `--text-xs` 或 `--text-sm`，技术标识仅在必要时保留等宽小字。
2. 将标题栏、配置卡操作、更多菜单和文本按钮的命中区域扩至规范下限，图标视觉尺寸可保持不变。
3. 为禁用输入区显示独立可读原因，不把关键说明只放在 placeholder 中。
4. 执行 Tab/Shift+Tab、Enter/Space、Escape、200% 缩放和读屏名称检查；对失败、保存成功等异步反馈确认 `aria-live` 行为。

### P2-1 产品术语与动作命名没有完全对齐【已实施】

当前问题：一级导航使用“新建复盘”“面试工作台”“会话复盘”，空状态又使用“和 Agent 开始对话”；设置导航叫“应用设置”，页内主标题却是“工作区设置”，而内容实际是应用级大模型配置。这些名称分别在表达会话、复盘、聊天、工作区和应用，用户难以形成稳定心智模型。

优化建议：围绕项目现有领域语言统一为“项目、复盘会话、岗位准备、项目资料、会话报告、能力画像、应用设置”。应用级模型与 Agent 配置应归入“应用设置”，不要称为“工作区设置”；输入区可写“回答当前问题”或“告诉 Agent 你的准备重点”，根据当前状态变化。

实施步骤：

1. 建立一份面向 UI 的术语表，明确“新建会话 / 开始复盘 / 会话复盘报告”等词的唯一含义。
2. 统一侧栏、页头、按钮、空状态和错误提示中的名称。
3. 修改文案测试与无障碍名称，确保视觉文本和可读标签一致。

### P2-2 浏览器预览仍展示桌面窗口控制【已实施】

当前问题：浏览器预览和移动视口仍显示主题、最小化、最大化、关闭按钮；除主题外，窗口控制在非 Tauri 环境不可执行，只会显示“窗口控制仅在 Tauri 桌面版可用”。这些控件在 390px 宽度下占用显著空间，并制造可操作错觉。

优化建议：仅在 Tauri 桌面环境显示最小化、最大化和关闭按钮；浏览器模式保留品牌与主题切换即可。移动端浏览器可进一步使用紧凑品牌栏，把更多垂直空间让给页面内容。

实施步骤：

1. 复用现有 `isTauriWindow` 判断，条件渲染系统窗口按钮，而不是点击后再提示不可用。
2. 为浏览器和 Tauri 分别定义标题栏布局，保持品牌和主题入口一致。
3. 验证浏览器桌面、浏览器移动端和 Tauri 三种环境，确保拖拽区域与窗口按钮只在桌面壳层出现。
